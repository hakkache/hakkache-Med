OpenLakehouse

A working Databricks-style data and AI platform that runs entirely on your own machine. Not a tutorial, not a diagram — real Spark jobs writing real Iceberg tables, real Trino queries against them, real Kafka change-data-capture streams, a real orchestrator and a real model registry, behind one login and one UI. Thirty-nine Docker services, one command.

View on GitHub Architecture doc Guided tutorial

Why it exists

Most "learn the modern data stack" guides ask you to stitch together a dozen SaaS trials or fight half-broken local installs. This is one command that gives you the whole thing — so you can learn it, prototype on it, or demo it without paying a cloud bill or handing your data to a vendor.

# control plane only — up in about a minute docker compose --profile core up -d --build # the full platform — 39 services docker compose --profile full up -d --build → http://localhost

Lakehouse core

Apache Spark writing Iceberg tables through an Apache Polaris REST catalog, stored on MinIO in bronze → silver → gold layers.

Query & BI

Trino as the SQL engine with saved queries and history; Apache Superset dashboards embedded directly in the app.

No-code pipeline builder

A visual graph — source → transform → quality gate → destination — compiling down to real Spark SQL against the live catalog.

Streaming & CDC

Kafka in KRaft mode with Debezium capturing Postgres changes in real time into the lakehouse.

Orchestration

Dagster schedules and sensors driving Spark jobs and dbt-core models built against Trino.

Quality & lineage

Not-null, unique, range, regex, schema, freshness and row-count checks with scoring, plus an auto-derived lineage graph and OpenMetadata catalog.

ML & notebooks

MLflow experiment tracking and model registry, with Jupyter pre-wired to the same Spark cluster.

Security

Keycloak issuing real OIDC/JWT tokens, five RBAC roles enforced server-side on every API call, OpenBao for secrets, Traefik as the single gateway.

Observability

Prometheus, Grafana, Loki and an OpenTelemetry collector pre-provisioned, so a slow Trino query traces back to the request that caused it.

AI assistant

A local LLM through Ollama wired into the platform for in-app help — no data leaves the machine.
